# 05 — UI/UX Specification and Interaction Contract

**Product:** CrewGrid · **Target:** complete React flow, keyboard-only usability, mobile responsive. The dark aesthetic is a design choice, **not** a scoring requirement; clarity and successful team management matter more.

## 1. UX goals and principles

1. **State clarity:** user always knows membership, pending requests, open seats and what action is allowed.
2. **Conflict transparency:** no silent failure. A full-seat race explains lost availability and refreshes state automatically.
3. **Accessible actions:** semantic buttons/inputs, visible focus, complete keyboard flows; not only hover controls or icon-only affordances.
4. **Fast navigation:** event switcher, dashboard, team discovery, teammate discovery, my team, profile.
5. **Truthful engineering evidence:** evidence page reads static artifacts generated by actual tests; never simulate a benchmark chart and label it real.
6. **Visual restraint:** high contrast, clear hierarchy, limited motion, dense data without clutter.

### Type hierarchy

- H1 `28–36px / semibold`, H2 `22–26px`, H3 `18–20px`, body `14–16px` with 1.5 line height, labels 13–14px; never rely on tiny 11px body text.
- Strong numeric readout `3 / 5` seats and clear Forming/Ready badges.
- Minimum touch target ~44px where practical; visible 2px focus ring.

## 4. Screen inventory with states and actions

### S-01 — Landing / evaluator entry

**Content:** Product value proposition, `Explore teams`, `Create account`, concise “built to survive the last-seat race” statement; walkthrough of how team joining works; footer repo/demo/report links when they actually exist. **Do not show fabricated stats**.  
**States:** signed-out hero; signed-in redirect to dashboard; broken deployment warning only when detected.  
**Interactions:** Create account, Sign in, Explore demo, Engineering evidence.  
**Mobile:** single column; compact menu; no hero animation dependency.

### S-02 — Register / login

**Fields:** email, password, displayName (register); email/password (login). Inline error, show/hide password, strong labels/autocomplete. Do not enumerate existing accounts in error messages.  
**States:** idle, validating, submitting (disable button/spinner), rate-limited countdown if server says, session-created redirect, invalid credentials.  
**Keyboard:** Enter submits; focus lands on first error summary and field.

### S-03 — Profile and onboarding

**Fields:** display name, unique public handle, optional bio, skills as removable chips (max 15), timezone IANA select/search, working hours and days, `Show me on teammate board` checkbox default **off**.  
**States:** dirty/saved/validation; timezone overlap preview; discoverability explanation.  
**Privacy copy:** public profile excludes email; toggle off removes from candidate board but not from team roster if already member.  
**Validation:** no unknown timezone, overlapping interval understood across midnight.

### S-04 — Event dashboard

**Content:** selected hackathon, membership summary, pending requests, suggested next action, quick links. If unassigned -> `Create a team` and `Find a team`; if team member -> `Open my team`, stage and roster; if leader -> requests to review.  
**States:** loading skeleton, no event, unassigned, forming team, ready team, leadership state.  
**Realtime:** membership change invalidates summary queries.

### S-05 — Live team board

**Content:** search, skill filter, Only open teams toggle, sort newest/availability, paginated 12-card list. Each card: team name, description excerpt, required skill chips, memberCount/maxSize, openSeats, stage and primary CTA.  
**CTA states:** `Request to Join`, `Request pending`, `Team full` (disabled), `View my team`, `Already on a team` (disabled), login required. Always provide explanation; never hide clickable intent without alternative.  
**Empty states:** no teams exist (create CTA), no filter matches (clear filters), backend failure (retry).  
**Realtime:** SSE invalidates list, display polite “Seats updated” rather than jumping scroll. Optional optimistic changes only for pending requests, never speculative membership success.

### S-06 — Team details

**Header:** team name, event, stage, open seats, required skills, description, members and leader badge.  
**Tabs:** Overview / Members / Activity (members); Requests/Invites/Suggestions (leader only).  
**Controls:** Request to Join, Create invite, Leave team, Edit team, Remove member, Transfer leadership. View permissions server-derived.  
**Critical dialogs:** confirmation for remove/leave/transfer with actor/team name and consequences. Browser `window.confirm` prohibited by UX design.  
**Race handling:** if approve fails due to full team, close loading, refresh both request list and team header, present non-dismissed alert `A seat was filled before your approval could complete`.

### S-07 — Leader request inbox / applicant requests

**Leader:** pending row with applicant name, skills, message, created date, Approve/Decline. Button disabled during submission; on 409, rollback optimistic status and refetch.  
**Applicant:** list of sent requests with Pending/Approved/Declined/Canceled and Cancel button if pending. A request does not reserve a seat; say so explicitly.  
**Accessibility:** confirmation messages announced by `aria-live=polite` and failures `role=alert`.

### S-08 — Looking for teammates board and leader suggestions

**Candidate board:** eligible opt-in unassigned profiles, skills, timezone, working-hour label; filter skill and timezone. Public profile must not reveal email.  
**Leader suggestions:** sorted match score, expanded explanation, component breakdown and suggested complementary skills. Explain score formula in UI. Primary CTA `Create invite to share`; no unimplemented “Send message” button.  
**Empty states:** no opted-in people, your team needs no extra skills, no overlap preferences provided.

### S-09 — Invitation creation/redeem

**Creation:** leader sets expiry, clicks Generate; one-time secret shown in copyable URL inside dialog and warned “copy now; not retrievable”. List previously generated invites shows status only, with revoke action.  
**Redeem:** leader shares `/invite#token=<base64url>`; browser fragment is not sent in HTTP request; client extracts token from `location.hash`, immediately calls `history.replaceState` to `/invite`, retains token only in transient memory; **do not** leak through analytics/logs/referrer; if unauthenticated, show an in-page sign-in/register form or modal so the transient token remains in memory through authentication (do not navigate away and lose it); show target team, explicit `Join with invite` and result.  
**Errors:** invalid/expired/used/revoked token, team full, existing membership. Generic public error to avoid token oracle; user-friendly authenticated guidance.  
**Never** send token to third-party telemetry or store in localStorage.

### S-10 — Activity/audit

**Content:** immutable chronological list with actor public name, action summary and timestamp in viewer local timezone. Leader-only detailed variants if needed; private data redacted.  
**Events:** team created/edited, joined/left/removed, leader transfer, request action, invite action, deleted.  
**State:** pagination and no events fallback, event read-only, no filtering of record history in DB.

### S-11 — Engineering evidence page (optional P1)

**Only verified data:** reproducible commands, GitHub Actions run URL, race test output excerpt, load-test report downloadable, environment. Include labels `Local benchmark` vs `Live demo`. Empty placeholder if not run.  
**Warning:** never show an unrun planned metric as achieved.

`AppShell`, `SidebarNav`, `MobileNav`, `PageHeader`, `TeamCard`, `SeatProgress`, `StageBadge`, `SkillPill`, `ProfileCard`, `ScoreBreakdown`, `TeamMemberRow`, `RequestRow`, `InviteModal`, `ConfirmDialog`, `EmptyState`, `ErrorPanel`, `ToastProvider`, `SkeletonCard`, `LiveConnectionStatus`, `AuditTimeline`, `AccessibleFieldError`, `EventSelector`, `MetricEvidence`.

## 7. Interaction / state matrix (must implement)

| Operation | Loading | Success | Conflict | Network failure |
|---|---|---|---|---|
| Create team | disable Save, keep form | navigate to team | already-member alert | retain data, retry same key |
| Apply to team | optimistic pending optional | pending badge | duplicate/full/state alert | restore CTA; retry option |
| Approve | disable button, row pending | move to resolved; update count | rollback + refresh + alert | keep request pending; retry same key |
| Redeem invite | disable submit | navigate team | safe token/capacity error | preserve transient token; retry same key |
| Leave | modal & pending | redirect dashboard | membership already changed -> refetch | modal error, retry same key |
| Transfer leader | modal & pending | new leader badge | target no longer member -> refetch | retain selection; retry |
| Edit capacity | pending | update summary | reduced below current count -> show current count | restore form |

## 8. Accessibility acceptance

- Navigate every function with Tab, Shift+Tab, Enter, Space, Escape, arrow keys for menus/selects as native patterns require.
- Dialogs trap focus, restore focus to trigger after close, support Escape and accessible titles/descriptions.
- Labels or `aria-label` for all icon-only controls; inline field error linked with `aria-describedby`.
- Visible focus ring, skip-to-content link, one H1 per page, semantic list/table structure.
- Button state announced when pending; status messages announced without stealing focus; high contrast text.
- Color never solely indicates state. Keyboard-only acceptance through signup → create → join/approve → leave.
- No essential pointer-only drag/reorder gesture. Respect reduced motion.
- Test `axe`/Playwright and manual keyboard flows at 375px and 1280px.

## 9. Copywriting conventions

Use concrete states. Examples: `3 of 5 seats filled`, `Request sent — a team leader will review it`, `Someone joined before your approval completed`, `You've already joined a team for this hackathon`, `This invite is no longer valid`. Avoid misleading `Reserved` label for pending requests.

## 10. Wireframes (content structure, not final visual mockups)

**Team board:** left nav | header (Event / Discover Teams) | search/filter toolbar | optional live connection indicator | card grid [name, stage, 3/5, skills, CTA] | pager.  
**Team detail:** left nav | breadcrumb | team header [name, 3/5, forming] | split overview/roster + activity | contextual leader controls right.  
**Leader requests:** headline + pending count | rows with profile summary, join message and Approve / Decline | informative conflict banner when full.  
**Suggestions:** criteria summary / score explanation | candidate ranked list | expandable score components and Generate Invite.

## 11. UI QA gates

No inert buttons. No API placeholder mocks in production. No personal data in screenshot fixtures. Every screen has loading/empty/error/success, role-specific visible actions, and screen-reader meaningful status. Browser back/forward must not bypass auth gates. No unverified benchmark numbers on dashboard.
